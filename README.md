# Komari 三网回程插件

为 yinpengfei 维护版 Komari 添加回程检测：默认每 60 分钟，后台可配置检测间隔和电信／联通／移动 IPv4、IPv6 目标，支持手动更新、历史记录及默认主题首页节点卡片。

版本：`0.1.0`。采集器支持 Linux amd64、arm64。目标是**节点到指定国内目标的回程方向**，不是去程；不代表全国同运营商的网络表现。CN2 GIA/GT 仅显示为规则推测。

## 安装

1. 使用 [本项目 Release](https://github.com/yinpengfei/komari-plugin-return-route/releases/tag/v0.1.0) 的 `komari-plugin-return-route-0.1.0.zip`，在 Komari 后台「插件」上传安装。
2. 启用插件并核对权限：系统 RPC（用于下发和读取节点任务）、注册 HTTP 路由、HTML 注入（用于首页卡片）。插件不请求服务端执行进程、额外监听端口或越界文件权限。
3. 进入后台「三网回程」，选择节点，配置检测间隔、历史天数及目标 IP，保存。默认北京三网；可填入上海、广州预置，或逐条编辑／移除地址。
4. 主动点击「安装／更新」：由现有 Agent 下载固定版本采集器、校验 SHA256，安装到 `/opt/komari-return-route/collector`。此动作要求 Agent 以 root 执行；普通用户需自行配置目录及原始 ICMP 套接字权限。不会自动修改权限或启用远程控制。
5. 点击「立即更新」，或等待后台定时任务。首页卡片需使用本维护版默认主题，支持 IPv4/IPv6 切换。第三方主题没有对应节点 DOM 时不强行注入。

采集节点必须允许 Agent 远程任务。`--disable-web-ssh` 或等价环境变量／JSON 为 true 时无法使用该执行方式；请按自己的策略决定是否启用，不需要为了查看历史开启权限。仅安装服务端插件不会安装节点采集器。

兼容基线：`yinpengfei/komari` 的 `1.5.2` 和 `yinpengfei/komari-agent` 的 `1.5.3`。不保证其他分支或同名上游版本具备相同插件 API。无需升级主程序。

## 配置与检测规则

- 默认 60 分钟，可设置 5–10080 分钟。历史默认 30 天，可设置 1–365 天。
- 最多 18 个目标；每个目标包含运营商 CT/CU/CM、地区、名称、IPv4/IPv6 和对应公网裸 IP。不接受域名、内网、链路本地地址或命令。
- 不需要某种地址族时移除相应目标。节点没有该网络、原始套接字权限不足、目标不响应时会保留失败信息。
- 每目标三次追踪，每次最多 30 跳，单次采集上限 180 秒、输出上限 1 MiB；同时最多检测两台节点，每节点最多一个任务。
- 节点在一分钟内错开，不依赖浏览器保持打开；手动与定时任务共用队列，重复请求不会再下发同节点任务。
- 预置来自 oneclickvirt/backtrace 的固定快照 `6c2b9ff7fe77c83132b9a141f118d8667d4e864c`，只是社区测试目标标签，不是运营商对服务可用性或地址归属的保证。地址可能失效，应按实际情况配置。
- IPv4 采用经过边界修正的已知网络地址特征，IPv6 使用内嵌前缀表最长匹配。仅按路径响应地址推断网络，不读取运营商真实 BGP AS_PATH。
- 多次结果不同显示动态混合，证据不足显示未知；中间跳不回复不能当成业务丢包。延迟／丢包监控继续使用独立 Ping 任务。

## 存储、备份与隐私

配置存入宿主的插件配置数据库。结果存放在宿主数据目录：

```text
data/plugin-data/return-route/
  latest/<UUID>.json
  history/YYYY-MM-DD/<UUID>.jsonl
  jobs.json
```

最新结果包含逐跳 IP/ASN、规则依据、目标、版本和采集时间。失败不会替换上次成功证据，而会更新「最近执行状态」；超过两个检测周期没有成功结果时显示过期。切换目标地址后不将旧地址结果当成新地址结果。

最新文件和任务状态采用同目录临时文件加原子替换；损坏状态会停止调度并报错，不会静默重置任务。升级插件保留此目录；**删除插件会连同数据一起删除**。备份完整 Komari `data` 目录；回滚前保留一份当前数据。

远程任务输出也会进入 Komari 的 TaskResult 数据表，本维护版宿主会清理超过 30 天的任务结果；任务元数据仍由宿主管理。插件不删除其他任务。插件自己的历史按配置天数清理。

公共页面仅返回可见节点的线路标签、目标名称／地区及检测时间；逐跳 IP、任务输出、错误详情、配置和操作仅供管理员查看。私有站点未登录访问被拒绝。

采集器运行时只对管理员配置的目标发 ICMP 探测，不访问 ASN API、公共 DNS、CDN 或更新源，不上传到第三方。被探测目标和途经网络可看到探测源 IP。安装／更新采集器时主动访问本项目 GitHub Release；固定版本及 SHA256 信息随插件 ZIP 一起发布。

## 手动安装与卸载采集器

管理员也可以从 Release 下载对应架构的二进制及 `SHA256SUMS`，校验后放入 `/opt/komari-return-route/collector`，运行 `--version` 应输出 `0.1.0`。后台点击安装／更新可登记版本。采集器没有常驻服务、计划任务或入站端口。

卸载时先暂停插件的自动检测，等待正在执行的任务结束，再移除确定属于本插件的 `/opt/komari-return-route/collector`。目录没有其他文件时再自行移除目录；保留 Komari 数据备份后决定是否删除插件。

## 开发与验证

```sh
go test ./...
node --test test/*.test.cjs
python3 scripts/package.py
```

打包脚本生成两种 Linux 二进制、校验值及插件 ZIP。`GO_BINARY` 可指定 Go 路径；打包需要 Go 1.25.11 和 Python 3。插件本身没有 npm 依赖。

`integration/` 使用真实 Komari 插件运行时、隔离 SQLite 库和模拟 Agent 任务验证下发、回传、权限及升级持久化；不连接线上节点。其 Go 模块替换路径要求 Komari 源码在本项目同级的 `repo/`。CI 固定使用宿主 1.5.2，并在 Linux amd64、arm64 上测试真实 ICMP 回环探测；这不等同于对你的云节点进行了实测。
